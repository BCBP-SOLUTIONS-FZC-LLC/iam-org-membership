# CLAUDE.md

This file provides guidance to Claude Code when working with the **Org & Membership (Core) Service** (`iam-org-membership`), a Go microservice in the IAM subsystem (Tender Management SaaS platform). Refines **IAM HLD v1.41 §5.6**; LLD v2.0 ("Org & Membership (Core) Service — Low-Level Design"), owner database `org_membership` on shared RDS PostgreSQL. Where LLD and HLD disagree, HLD is authoritative.

This repo is mid-way through a **service decomposition** (ADR-0007 + ADR-0008): departments/plans catalog ownership moved to **Catalog / Admin Config Service** (`iam-catalog-admin`), SAML group→dept/role mapping moved to **Group Mapping / JIT Config Service** (`iam-group-mapping`), tender ACL overlays moved to **Tender ACL Service** (`iam-tender-acl`), and delegation grants + OOO coordination moved to **Delegation Service** (`iam-delegation`). This repo — "Core" — is what's left after all four extractions; the removal has already landed on this branch (pre-production, no staged expand/contract needed).

## What This Repo Is

`iam-org-membership` is a **private Go service** (module: `github.com/BCBP-SOLUTIONS-FZC-LLC/iam-org-membership`) that owns the **organizational layer** of the IAM platform: how users are grouped into tenants and departments, what roles they hold, and how tenants are structured and entitled. Keycloak owns authentication; User Profile owns presentation identity; this service owns the business domain model. It is the source of truth consumed by **AuthZ Enrichment** via `GET /api/v1/internal/users/:id/memberships` (I-8) — the hottest path in the system, hit on every authenticated request.

**Key responsibilities (sole writer for):**
- **Tenants** — plan (ENUM, not FK), subscription status, trial metadata, realm identity/type/shard, MFA freshness, locale, `local_accounts_enabled`, licensed seats, ownerless/overage/realm-sync markers. No longer carries `delegation_max_duration_days`/`delegation_review_window_days` (moved to Delegation Service's own `delegation_tenant_settings`).
- **Department activation** (`tenant_departments`) — per-tenant activation junction only; the global department catalog itself lives in Catalog Service, validated app-side against an `om:departments` read-through cache, not a local FK.
- **Tenant memberships** (`tenant_memberships`) — lifecycle only, no role data (§16 A14)
- **Tenant-level role grants** (`tenant_roles`) — `tenant_owner`/`tenant_admin`/`tender_admin` only; `member` **derived at read time**, never persisted (TR-7, §16 A29)
- **Department memberships** (`dept_memberships`) — user↔department↔role-level (`preparator`/`reviewer`/`approver`); + `dept_role_labels` (tenant-customizable display labels, presentation only — no group→role mapping data, that moved to Group Mapping Service)
- **Pending invitations** (`pending_invitations`, new §16 A11) — two-step invite→accept staging (**one PII exception**: email + full_name until acceptance)
- **Plan tier / feature-flag overrides** — `tenants.plan` (ENUM) and `tenants.feature_flags` (per-tenant delta only, T-9); effective set = `planDefaults(plan) ∪ feature_flags` at read time, `planDefaults` now sourced from Catalog Service via `om:plans` read-through cache instead of a local `plans` table

**Does NOT own:** credentials, MFA enforcement, JWT issuance (Keycloak); display identity, signature, OOO presentation flag (User Profile); global department catalog / plan entitlement catalog (Catalog / Admin Config Service); group→dept/role JIT mapping tables (Group Mapping / JIT Config Service); tender ACL overlay `tender_acl_entries` (Tender ACL Service); delegation record/lifecycle/policy/events `delegations` (Delegation Service); realm/Keycloak Admin API mutations (Realm Provisioner — this service **never** calls Keycloak Admin API); workflow template authoring or `assignee_overrides` state (Workflow Service — we validate + emit `TenderAssigneeOverridden` via I-13, never persist; §16 A32(d)/OVR-1); audit records (Audit Log); tender content/bids (Tender Service); metered resource consumption / quota enforcement (Usage & Metering — HLD §10.6 "IAM does not count tokens or requests itself"); pricing / currency (Billing — `default_currency` deliberately not stored here, §16 A32(b)/T-3).

**Core's only remaining delegation touchpoint:** a synchronous delegate-impact gate on user removal (§8.8, via `port.WorkflowClient` — talks to the *Workflow* Service, unaffected by the decomposition) plus a synchronous department-scope precision lookup on the admin dept-membership Assign/Remove path via `port.DelegationCheckClient` → `GET {DELEGATION_BASE_URL}/internal/delegations/dept-delegate`. On Delegation Service outage this degrades to tenant-wide impact scoping (still correct, less precise) — never a hard failure. There is no `port.UserProfileClient`/`userprofile` adapter in this repo any more — the old `SetAvailability` OOO-coordination flow was dead code once delegation moved out and has been deleted (LLD §16 OQ-5).

## Architecture

Clean Architecture — dependencies point inward; outer layers never import inner layers. Full directory tree, shared library dependencies (`platform-gincommon` v1.2.0, `platform-events` v1.4.0, `platform-pgcommon` v1.1.1), `RoutingPublisher` two-topic wiring, and `go-arch-lint` dependency rules are in **[`.claude/architecture.md`](architecture.md)**.

## Key Files to Know

- **`cmd/server/main.go`** — wiring, pool setup (`pgcommon.NewPool` with `GUCProvider = GUCSetFromContext` → transaction-local `app.tenant_id` binding on every checkout, RLS-6), middleware, graceful shutdown, plus 4 in-process metric-exporter goroutines (`iam_tenant_ownerless`, `iam_realm_sync_pending`, `iam_seat_overage_active`, `iam_pending_invitations_stale`) started alongside the outbox runner. K8s CronJobs count is **7** (write-side reconcilers dispatched by `cmd/reconciler/main.go --job=<name>`, single binary) — exporters are goroutines, not CronJobs. See `operations.md`.
- **`internal/core/domain/*.go`** — entities, value objects, `DomainError` catalogue (`ErrWorkflowResolutionRequired`, `ErrSeatLimitReached`, `ErrInvitationAlreadyExists`, `ErrInvalidReplacement`, `ErrConflict`). No `delegation.go`/`tender_acl.go` (removed). No external deps.
- **`internal/core/service/membership_service.go`** — most complex service. `RemoveUser` synchronously calls `port.WorkflowClient.GetDelegateImpact` before removal cascade; on `active_workflows > 0` returns `409 workflow_resolution_required`, resolved via `POST /tenants/:id/users/:user_id/removal-resolution` (P-26, `replace_delegate`/`stop_workflows`). Removal cascade also soft-deletes `tenant_roles` in the same `RunInTx` (step 1b, TR-9), then emits one `MembershipRevoked{tenant_id,user_id,actor_id}` (consumed by both Delegation Service and Tender-ACL Service for their own async cascades — Core owns neither table any more). Also handles department-level demotion/removal gating (§8.8.4, precision-scoped via `port.DelegationCheckClient`, degrades to tenant-wide scoping on Delegation Service outage), suspension advisory (§8.8.5, fail-open WFI-13), invitation lifecycle (§8.10 — `Invite`, `AcceptInvitation` via I-3), SEAT-1 transactional cap enforcement, TM-8 last-owner protection + TM-13 concurrency serialization (owner-affecting mutations take `SELECT … FOR UPDATE` on `tenants` row), TM-12 identity-layer escalation (`ownerless_since`). There is no `internal/core/service/delegation_service.go`/`tender_acl_service.go` in this repo — that logic moved to Delegation Service / Tender ACL Service.
- **`internal/core/service/catalog_service.go`** / **`group_mapping_service.go`** — client-side read-through wrappers (cache + stale-if-error), NOT table owners: `catalog_service.go` resolves `om:plans`/`om:departments` from Catalog Service (`catalogadmin` client, NOT fail-open — surfaces `catalog_unavailable` 503 on cold-cache-plus-failure); `group_mapping_service.go` resolves `om:grm`/`om:gdm`/`om:gtrm` from Group Mapping Service (`groupmappingclient`, fails OPEN — empty resolution, HTTP 200, so a SAML login never fails on this call).
- **`internal/core/port/outbound_clients.go`** — `WorkflowClient` (§8.8.1, `GetDelegateImpact`/`ReassignDelegate`/`CancelByDelegate`, talks to Workflow Service, unaffected by the decomposition), `RealmProvisionerClient` (`CreateInvitedUser`, `DeleteUser` idempotent PI-9, `PatchRealmConfig` T-15 Option A local-first + reconcile, `RevokeUserSessions` AUTH-8 best-effort fail-open), `DelegationCheckClient` (new, ADR-0008 — replaces the local `DelegationRepository` this repo used to have; `GET /internal/delegations/dept-delegate` dept-scoped precision lookup), `CatalogAdminClient` (new, ADR-0007 — `GET /internal/plans`, `GET /internal/departments`). No `UserProfileClient` — removed as dead code, zero call sites once delegation's OOO coordination moved out (LLD §16 OQ-5).
- **`internal/core/port/group_mapping_client.go`** — `GroupMappingClient` (new, ADR-0007 — `POST /internal/tenants/:id/group-resolution`, SAML/OIDC JIT resolution for I-10).
- **`internal/adapter/inbound/http/membership_handler.go`** — `DELETE` pre-check; `POST .../removal-resolution` (P-26); invite lifecycle (P-6/P-30/P-31); seat-usage (P-27).
- **`internal/adapter/inbound/http/internal_handler.go`** — I-13 `POST …/assignee-override` (validate-and-emit `TenderAssigneeOverridden`, never persists, OVR-1, §16 A55); I-14 `GET …/mfa-freshness` (returns `mfa_freshness_seconds` from `om:tenant` cache — authoritative read path for AuthZ Enrichment step-up gate, §16 A72; modeled on I-9); I-15 `GET …/members/:user_id/exists` (new, ADR-0007/0008 — grant-time membership-existence check for Tender ACL Service and Delegation Service, replacing the composite membership FKs both lost when their tables moved to separate databases; never 404s); I-8 now projects `subscription_status` + derived `read_only` (§16 A53) via a **four-table join** (`tenant_memberships ⋈ tenants ⋈ tenant_roles ⋈ dept_memberships`), no delegations join. I-12 (tender ACL check) is retired — moved to Tender ACL Service. There is no `delegation_handler.go`/`acl_handler.go` in this repo.
- **`internal/adapter/inbound/consumer/membership_event_consumer.go`** — SQS handlers for `tenant-orgm-q`/`billing-orgm-q`. **EVT-14** recency guard (event `time` vs `tenants.last_event_at` under row lock — silently skips stale, still records `processed_events`); **EVT-15** future-time clamp (`event.time > now() + MAX_LIFECYCLE_EVENT_SKEW_SECONDS` → DLQ, not recorded); **EVT-16** tenant-state relay (re-emits `TenantStateChanged` on `iam.membership.events` in the same tx when a consumed event changes `status`/`plan`, sparing Workflow a direct `iam.tenant.events`/`billing.events` subscription); also emits `TenantMembershipsPurged{tenant_id,actor_id}` (renamed from the old `TenantOffboarded`-named relay — that name collided with RP's own terminal event, which Core only consumes) when a consumed event transitions a tenant to `offboarded`, for Delegation/Tender-ACL/Group-Mapping to run their own tenant-scoped cascade-deletes.
- **`internal/adapter/outbound/postgres/*_repository.go`** — implements all `core/port` repositories; 7 of the 8 tables carry `record_version` and use `UPDATE ... WHERE id=$1 AND record_version=$2` optimistic locking (409 `optimistic_lock_conflict`, TRG-1 client never sets `record_version`); `processed_events` is the exception.
- **`internal/adapter/outbound/eventbus/publisher.go`** — `events.NewRoutingPublisher` (two topics by `Envelope.Source`) + outbox runner; UUID v7 event IDs; `processed_events` composite PK 8-day retention (PE-1 strictly > 7-day SQS lifetime; IDEMP-4 beyond-window duplicates backstopped by EVT-14/PI-10/IDEMP-3). All published events carry `ip_address`/`user_agent` envelope fields (`platform-events` v1.4.0 `WithIPAddress`/`WithUserAgent`, §16 A69); CronJob-originated events use sentinel `ip_address: "system"` / `user_agent: "iam-org-membership/<job-name>-cron"`.
- **`internal/adapter/outbound/{workflow,realmprovisioner,catalogadmin,groupmappingclient,delegationcheck}/http_client.go`** — five outbound service clients, identical construction pattern (`gincommon.PropagateHeaders`, configurable `*_TIMEOUT_MS` env var); `catalogadmin`/`groupmappingclient` are read-only and errors are never fabricated into safe defaults — resilience is the caller's `CatalogService`/`GroupMappingService` cache + stale-if-error layer, not the client. `delegationcheck` (new, ADR-0008) backs the §8.8.4 dept-scope precision lookup and fails open to tenant-wide scoping. There is no `userprofile/` package — deleted as dead code (LLD §16 OQ-5).
- **`internal/adapter/outbound/eventbus/schemas/*.json`** — schema-governance workspace, one JSON Schema Draft-07 file per event type, embedded via `//go:embed schemas/*.json` in the `ValidatingCodec`. Derived via `schema-gov extract`; CI `extract --check` for drift. (There is no separate `internal/eventschema/` directory — this is the one workspace.)
- **`api/asyncapi.yaml`** — design-time source of truth for two-topic event contract (`iam.membership.events` + `iam.tenant.events`). `api/openapi.yaml` has been deleted — the REST contract is now `docs/swagger/*` (generated via `make swag`), not hand-authored.
- **`docs/swagger/swagger.yaml`** (generated via `make swag` from handler annotations, not hand-authored) — REST contract for all public/internal/operator routes (P-1..13,24-28,30-31; I-1..5,8-11,13-15; O-4,O-7 — 34 total). Retired route IDs (P-14..23,29,32,33; I-6,7,12; O-1,2,3,5,6) are fully unregistered, not 410 Gone, and never reused.
- **`test/postgres/rls_test.go`** — canonical RLS test cases including **Case 5** (critical): no cross-tenant GUC leak across a pooled PgBouncer connection (verifies RLS-6). CI additionally greps for non-`LOCAL` `SET app.tenant_id` as forbidden pattern.

## Data Model

Database `org_membership` on RDS PostgreSQL (Multi-AZ, PgBouncer transaction pooling); **8 tables** (`tenants`, `tenant_departments`, `tenant_memberships`, `tenant_roles`, `dept_memberships`, `dept_role_labels`, `pending_invitations`, `processed_events` — `departments`/`plans`/group-mapping tables/`tender_acl_entries`/`delegations` moved to the Catalog, Group Mapping, Tender ACL, and Delegation services respectively — the current schema is a single consolidated migration, `000000_initial_schema`, since this service has never been deployed and the incremental decomposition history had no live data to protect) with RLS on all 7 tenant-scoped tables (`FORCE ROW LEVEL SECURITY` + `REVOKE ALL FROM PUBLIC` + `tenant_isolation` policy on `app.tenant_id`), `record_version`-based optimistic locking on 7 tables (all except `processed_events`), and partial unique indexes (`WHERE deleted_at IS NULL` / `WHERE status='pending'`) so a user can rejoin a tenant/department previously left. Some cross-database FKs were lost in the split and replaced by synchronous app-level checks (`tenants.plan`/`tenant_departments.department_id`/`dept_memberships.department_id` against `om:plans`/`om:departments`; Tender ACL and Delegation now call Core's new I-15 existence check instead of a composite membership FK). Full table catalogue, RLS invariants (RLS-1..RLS-6), tenant invariants (T-1..T-15), seat invariants (SEAT-1..SEAT-5), migration invariants (MIG-1..MIG-9), and trigger behavior (`touch_row`, `trg_tenant_slug_immutable`) in **[`.claude/database-schema.md`](database-schema.md)**.

## API, Caching & Events

Three route prefixes (`/api/v1/*`, `/api/v1/internal/*`, `/api/v1/operator/*`); hot-path lookup at `GET /internal/users/:id/memberships` (I-8, SLO 15 ms hit / 30 ms miss, includes `subscription_status`/`read_only`, four-table join with no delegations join). **34 active endpoints**: public P-1..13,24-28,30-31 (20), internal I-1..5,8-11,13-15 (12, including new I-15 membership-existence check for Tender ACL/Delegation), operator O-4,O-7 (2). Retired IDs (P-14..23,29,32,33 — group-mapping admin CRUD, delegation list/create/cancel/extend/reassign, tender-ACL grant/list/revoke, all moved to their respective new services; I-6,7,12 — quotas retired earlier, tender-ACL check moved out; O-1,2,3,5,6 — dept/plan catalog admin moved to Catalog Service) are fully unregistered, never reused. Valkey cache advisory-only (CACHE-2/CACHE-9); new read-through keys `om:plans`/`om:departments` (Catalog Service) and `om:grm`/`om:gdm`/`om:gtrm` (Group Mapping Service, `:stale` 24h fallback). Two SNS outbound topics via `RoutingPublisher`: `iam.membership.events` (`DepartmentMembershipGranted/Revoked/LevelChanged`, `TenantRoleGranted/Revoked`, `MembershipRevoked` — shared per-user removal signal consumed by both Delegation and Tender-ACL services, `TenderAssigneeOverridden`, `TenantSeatOverageStarted/Resolved`, `TenantStateChanged` relay §16 A61, `TenantMembershipsPurged` — tenant-level cascade signal, renamed from the old `TenantOffboarded`-named relay to avoid colliding with RP's own event of that name); `iam.tenant.events` with only `TenantCreated`/`TrialStarted` produced by Core (everything else on that topic is RP-produced and only consumed). `DelegationStarted`/`DelegationEnded`/`DelegationReviewRequested` are gone — moved to Delegation Service's own `iam.delegation.events` topic; their schemas are deleted from this repo. All published events carry `ip_address`/`user_agent` envelope fields (§16 A69). Two inbound SQS queues (`tenant-orgm-q`, `billing-orgm-q`) with EVT-14 recency guard + EVT-15 future-time clamp + EVT-16 relay. CloudEvents envelope, `platform-schemagov` governance. Full endpoint catalogue, cache TTLs + invalidation, event lists + payloads, and status-code table in **[`.claude/api-caching-events.md`](api-caching-events.md)**.

## Request Flows & Concurrency

Trial signup (§8.1: 5 default system depts — Engineering, Design, Procurement, Finance, Legal — activated over the (now Catalog-Service-owned) global department catalog + 3 role labels + owner + role grant + 2 events in one tx, all inside the `TrialTenantProvisioned` consumer, not I-1); AuthZ hot-path lookup (§8.3); JIT SAML (§8.5, additive-only GTRM-4, resolution now a Group Mapping Service call via `port.GroupMappingClient`, not local tables); user removal with delegate-impact resolution (§8.8: pre-check via `port.WorkflowClient` against the *Workflow* Service — unaffected by the decomposition, P-26 `replace_delegate`/`stop_workflows`, `tenant_roles` soft-deleted in cascade TR-9, one `MembershipRevoked` emission shared by Delegation Service and Tender-ACL Service, department-level extension §8.8.4 now precision-scoped via `port.DelegationCheckClient`'s dept-delegate lookup with tenant-wide degrade-on-outage, suspension advisory §8.8.5 fail-open); two-step invite→accept (§8.10, seat-hold on stage, `kc_cleanup_pending` durable compensation PI-9); optimistic locking (CONC-1..4); idempotency (IDEMP-1..4 with EVT-14/PI-10/IDEMP-3 as beyond-window backstop); consistency (CONS-1..4 write+event atomic via transactional outbox); GDPR (§15.2.2: soft-delete pattern, `pending_invitations` erasure-by-email is the sole non-`user_id`-keyed path; on tenant offboarding Core scrubs its own `tenants` row + `ON DELETE CASCADE` for its own tables, then emits `TenantMembershipsPurged` so Delegation/Tender-ACL/Group-Mapping run their own tenant-scoped cascades in their separate databases). Core no longer coordinates OOO delegation or runs any delegation-review/expiry flow itself — that entire flow (§8.6/§8.7 of the old LLD) moved to Delegation Service; Core's only delegation-adjacent logic is the §8.8/§8.8.4 gates above. Full flow diagrams and invariants in **[`.claude/request-flows.md`](request-flows.md)**.

## Operations

Security (three-layer isolation, AUTH-8 privilege-reduction with RP session revoke + TTL backstop, AUTH-7 defense-in-depth for operator routes); observability (SLO-1..3, `iam_`-prefixed metrics with `job` label for subsystem-wide dashboards, cardinality guardrails §16 A48, alert routing; new cross-service-call metrics `iam_xsvc_call_latency_seconds`/`iam_xsvc_call_errors_total` (labels include `service` = catalog|group_mapping|delegation) and `iam_membership_exists_check_total` for I-15; no `iam_delegation_*` metrics — that whole class moved to Delegation Service); configuration (`DATABASE_URL`, `WORKFLOW_SERVICE_BASE_URL`, `INVITATION_EXPIRY_DAYS=7` coupled to KC action-token lifespan, `SEAT_OVERAGE_GRACE_DAYS=30`, `MAX_LIFECYCLE_EVENT_SKEW_SECONDS=300`; new `CATALOG_ADMIN_BASE_URL`/`CATALOG_ADMIN_TIMEOUT_MS` (not fail-open), `GROUP_MAPPING_BASE_URL`/`GROUP_MAPPING_TIMEOUT_MS` (fails open), `DELEGATION_BASE_URL`/`DELEGATION_TIMEOUT_MS` (fails open — added in the decomposition pass after being found missing from `.env-example`/Helm values in every environment); `USER_PROFILE_SERVICE_BASE_URL`/`USER_PROFILE_TIMEOUT_MS` and `DELEGATION_REVIEW_WINDOW_DAYS` removed (dead adapter deleted; setting moved to Delegation Service's own `delegation_tenant_settings`)); deployment (HPA 2–8, **7 CronJobs** dispatched via `cmd/reconciler --job=<name>`: `invitation-expiry`/`invitation-kc-cleanup`/`realm-config-sync`/`seat-overage-reconcile`/`trial-cleanup`/`outbox-prune`/`processed-events-prune` — `delegation-expiry`/`delegation-review`/`delegation-cleanup` moved to Delegation Service, `acl-cleanup` moved to Tender ACL Service. The four metric exporters run as ticker goroutines inside `cmd/server/main.go` per the sibling `iam-user-profile2` pattern — not as CronJobs. Additive-then-destructive migrations MIG-1); testing (unit mocks including AUTH-8 fake `RealmProvisionerClient`, integration testcontainers covering EVT-14/15/16 + composite FKs + TM-12/TM-13 + T-15 reconciler, contract tests, e2e/smoke, RLS Case 5); §20.7 fail-open vs fail-closed dependency matrix (Catalog Service is the one NOT fail-open — surfaces `catalog_unavailable` 503; Group Mapping and Delegation clients both fail open); §21 performance.

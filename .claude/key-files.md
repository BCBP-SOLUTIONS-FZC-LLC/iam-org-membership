# Key Files to Know

Critical implementation files for `iam-org-membership`. See also [`architecture.md`](architecture.md) for directory tree and layer rules.

- **`cmd/server/main.go`** — wiring, pool setup (`pgcommon.NewPool` with `GUCProvider = GUCSetFromContext` → transaction-local `app.tenant_id` binding on every checkout, RLS-6), middleware, graceful shutdown, plus 5 in-process metric-exporter goroutines (`iam_org_membership_tenant_ownerless`, `iam_org_membership_realm_sync_pending`, `iam_org_membership_seat_overage_active`, `iam_org_membership_pending_invitations_stale`, and `iam_rls_violations_total` — backed by `pgadapter.GaugeRepository.RLSViolationCounts`, wired in 2026-09-21) started alongside the outbox runner via `runBusinessExporters` (`cmd/server/exporters.go`). K8s CronJobs count is **7** (write-side reconcilers dispatched by `cmd/reconciler/main.go --job=<name>`, single binary) — exporters are goroutines, not CronJobs. Schema migrations are **not** run by the replicas in Kubernetes: `cmd/migrate` (`postgres.MigrateSchema`) runs once per release as a Helm pre-install/pre-upgrade hook Job and the Deployment sets `RUN_MIGRATIONS=false`; unset or true (local dev, tests), the server migrates at startup. See `operations.md`.
- **`internal/core/domain/*.go`** — entities, value objects, `DomainError` catalogue (`ErrWorkflowResolutionRequired`, `ErrSeatLimitReached`, `ErrInvitationAlreadyExists`, `ErrInvalidReplacement`, `ErrConflict`). No `delegation.go`/`tender_acl.go` (removed). No external deps.
- **`internal/core/service/membership_service.go`** — most complex service. `RemoveUser` synchronously calls `port.WorkflowClient.GetDelegateImpact` before removal cascade; on `active_workflows > 0` returns `409 workflow_resolution_required`, resolved via `POST /tenants/:id/users/:user_id/removal-resolution` (P-26, `replace_delegate`/`stop_workflows`). Removal cascade also soft-deletes `tenant_roles` in the same `RunInTx` (step 1b, TR-9), then emits one `MembershipRevoked{tenant_id,user_id,actor_id}` (consumed by Delegation Service and Tender-ACL Service for their own async cascades — Core owns neither table any more — and by AuthZ Enrichment on `membership-authz-q` for `om:memberships` cache eviction). Also handles department-level demotion/removal gating (§8.8.4, precision-scoped via `port.DelegationCheckClient`, degrades to tenant-wide scoping on Delegation Service outage), suspension advisory (§8.8.5, fail-open WFI-13), invitation lifecycle (§8.10 — `Invite`, `AcceptInvitation` via I-3), SEAT-1 transactional cap enforcement, TM-8 last-owner protection + TM-13 concurrency serialization (owner-affecting mutations take `SELECT … FOR UPDATE` on `tenants` row), TM-12 identity-layer escalation (`ownerless_since`). There is no `internal/core/service/delegation_service.go`/`tender_acl_service.go` in this repo — that logic moved to Delegation Service / Tender ACL Service.
- **`internal/core/service/catalog_service.go`** / **`group_mapping_service.go`** — client-side read-through wrappers (cache + stale-if-error), NOT table owners: `catalog_service.go` resolves `om:plans`/`om:departments` from Catalog Service (`catalogadmin` client, NOT fail-open — surfaces `catalog_unavailable` 503 on cold-cache-plus-failure); `group_mapping_service.go` resolves `om:grm`/`om:gdm`/`om:gtrm` from Group Mapping Service (`groupmappingclient`, fails OPEN — empty resolution, HTTP 200, so a SAML login never fails on this call).
- **`internal/core/service/authz_service.go`** — I-8's business-logic composition (TR-7 derived-role injection, PLAN-6 feature-flag merge, graceful degradation on a Catalog Service outage). Depends on a new `port.AuthZRepository`, not `*pgcommon.Pool` directly — the four-table join itself now lives in `internal/adapter/outbound/postgres/authz_repository.go` (`AuthZRepository.FindMembershipProjection`). This split (a Clean-Architecture fix landed alongside I-16) is what makes I-8 unit-testable with a hand-written fake, no Postgres container required. **Two AuthZ Enrichment compatibility invariants that must never be broken without cross-service coordination:** (1) `DeptMembershipView.RoleLevel` is serialised as `json:"role_level"` in the I-8 response — AuthZ Enrichment explicitly parses this field name; changing it to `level` or `role` would silently break all department-level authz decisions. Note the intentional asymmetry: the *event* payloads (`DepartmentMembershipGranted`) use `json:"level"`, not `role_level` — two different field names for the same concept in two different protocol contexts, both correct and tested. (2) `MembershipProjection.MFAFreshnessSeconds` (`json:"mfa_freshness_seconds"`) is present in the I-8 response but **AuthZ Enrichment deliberately does not cache it** (caching it would be a security regression — a stale value could suppress the Approver step-up gate). AuthZ calls I-14 fresh on every approver-gated request instead. Do not remove `mfa_freshness_seconds` from I-8 (other consumers may read it), but do not assume it is the authoritative path for the MFA gate.
- **`internal/core/port/outbound_clients.go`** — `WorkflowClient` (§8.8.1, `GetDelegateImpact`/`ReassignDelegate`/`CancelByDelegate`, talks to Workflow Service, unaffected by the decomposition), `RealmProvisionerClient` (`CreateInvitedUser` — `RequiredActions` computed by `InvitationService.Invite` from `initial_tenant_roles`/`initial_dept_mappings` and sent verbatim, RP applies it as-is (RP-5, F5 resolved), `DeleteUser` idempotent PI-9, `PatchRealmConfig` T-15 Option A local-first + reconcile, `RevokeUserSessions` AUTH-8 best-effort fail-open, `ResetMFA` RP-9 fail-closed — LLD §16 OQ-8/F6, promoted onto the interface once **P-34** shipped as its caller), `DelegationCheckClient` (new, ADR-0008 — replaces the local `DelegationRepository` this repo used to have; `GET /internal/delegations/dept-delegate` dept-scoped precision lookup), `CatalogAdminClient` (new, ADR-0007 — `GET /internal/plans`, `GET /internal/departments`), `TokenServiceClient` (new, AUTH-9/IB-3 — `IsServiceAccount(ctx, tenantID, userID)`, backs the membership-create (P-6/I-3) and role-grant (P-10/P-28) defense-in-depth reject; `GET {TOKEN_SERVICE_BASE_URL}/service-accounts?principal_sub=` (Token Service's TS-5), fails open — an empty/unreachable value degrades to allowing the operation since the primary guarantee is the structural composite-FK bar, TR-8/DM-4). No `UserProfileClient` — removed as dead code, zero call sites once delegation's OOO coordination moved out (LLD §16 OQ-5).
- **`internal/core/port/group_mapping_client.go`** — `GroupMappingClient` (new, ADR-0007 — `POST /internal/tenants/:id/group-resolution`, SAML/OIDC JIT resolution for I-10). **Forward-compatibility note:** `groupmappingclient/http_client.go` type-casts GM-I1's `role_code` strings directly to `domain.DeptRole`/`domain.TenantRoleCode` without validation — safe today (GM only returns known enum values), but if Group Mapping's role enum expands, Core would silently accept unknown values and fail downstream. GM-I1's response also includes extra fields (`id`, `tenant_id`, `record_version`, `created_at`, `updated_at`) that Core's parser intentionally ignores via Go's default JSON behaviour.
- **`internal/adapter/inbound/http/membership_handler.go`** — `DELETE` pre-check; `POST .../removal-resolution` (P-26); invite lifecycle (P-6/P-30/P-31); seat-usage (P-27); `POST .../reset-mfa` (P-34, new — §16 OQ-8/F6, fail-closed on RP-9 outage).
- **`internal/adapter/inbound/http/internal_handler.go`** — I-13 `POST …/assignee-override` (validate-and-emit `TenderAssigneeOverridden`, never persists, OVR-1, §16 A55); I-14 `GET …/mfa-freshness` (returns `mfa_freshness_seconds` from `om:tenant` cache — authoritative read path for AuthZ Enrichment step-up gate, §16 A72; modeled on I-9); I-15 `GET …/members/:user_id/exists` (new, ADR-0007/0008 — grant-time membership-existence check for Tender ACL Service and Delegation Service, replacing the composite membership FKs both lost when their tables moved to separate databases; never 404s); I-8 now projects `subscription_status` + derived `read_only` (§16 A53) via a **four-table join** (`tenant_memberships ⋈ tenants ⋈ tenant_roles ⋈ dept_memberships`), no delegations join. I-12 (tender ACL check) is retired — moved to Tender ACL Service. There is no `delegation_handler.go`/`acl_handler.go` in this repo.
- **`internal/adapter/inbound/http/path_tenant.go`** — two tenant guards. `RequirePathTenantMatch` (API-2, public): on the `/api/v1/tenants/:id` group, rejects path ≠ `x-tenant-id` with `403 INSUFFICIENT_ROLE` (`PublicTenantMismatchDetail`) before the activity gates; never rebinds; `TestPublicTenantRoutes_AllRequirePathTenantMatch` fails CI for a tenant-facing route outside the group. `BindPathTenant` (IAPI-6), registered only on the `/internal/tenants/:id` route group in `router.go`: validates `:id`, binds it as `app.tenant_id` + `RequestContext.TenantID` via `requestctx.WithTenant` (caller user/roles/IP/UA untouched); a differing `x-tenant-id` is logged (`tenant_header_path_mismatch`) and counted (`iam_org_membership_tenant_header_path_mismatch_total`), or rejected `400 TENANT_MISMATCH` (`TenantMismatchType`, `{base}/iam/tenant-mismatch`) when `RouterConfig.StrictTenantPathValidation` (`STRICT_TENANT_PATH_VALIDATION`) is on. A new tenant-scoped internal route must be registered on `tenantScoped`, not `internal` — `TestInternalTenantRoutes_AllBindPathTenant` (`router_path_tenant_test.go`) fails CI otherwise. I-8 (`/users/:id`) binds its `?tenant_id=` in `GetMemberships` instead.
- **`internal/adapter/inbound/http/middleware.go`** — `HandleError` (RFC 9457 `application/problem+json` via `gincommon.AbortWithProblem`; `domainErrorToProblem` maps every domain sentinel to a platform type + UPPER_SNAKE `errorCode` via `.WithCode(strings.ToUpper(de.Code))`; `toDomainProblem` attaches `DomainError.Details` as RFC 9457 §3.2 extension members through platform-gincommon v2.1.0's `WithExtensions` (`active_workflows`, `licensed_seats`, `record_version`, `retry_after_seconds` etc.), so the library serialises them — there is no hand-written problem serialiser; CD-31 resolved, LLD rev 2.29, extensions rev 2.35); `NormalizeAuthErrors` (adds service-specific codes — `missing_identity_headers`/`ambiguous_identity_headers`/`invalid_request_context` — to gincommon's own 401/400 bodies); `GUCBridgeMiddleware` (binds `app.tenant_id` transaction-locally, RLS-6); `RequireJSONContentType`; role/tenant gates (`RequireRoles`, `RequireTenantOwner`, `RequireInternalCaller`, `RequireOperatorRole`).
- **`pkg/requestctx/guc.go`** — `WithSystemTenant(ctx, tenantID)`/`WithTenant(ctx, tenantID)`, the canonical helpers for internal/iam-system code paths (I-1..5,8-11,13-16, SQS consumers, reconcilers) to (re)bind the `app.tenant_id`/`app.user_id` RLS GUC to a specific target tenant regardless of the ambient caller context — the load-bearing invariant behind every "path `:id` is authoritative, not the caller's header" internal route. `WithSystemTenant` also stamps `app.user_id = "iam-system"`; `WithTenant` leaves the caller's own `user_id` untouched (used by O-4/O-7 operator routes so the path tenant is scoped without impersonating iam-system).
- **`internal/adapter/inbound/consumer/dedup.go`** — `processOnce`/`ackUnknown`, the IDEMP-1..4 helpers over `port.Inbox`: the processed_events claim (platform-events' `inbox.Store.Process`, via `postgres.InboxRepository` in `idempotency_repository.go`) and the handler's writes commit in one transaction, the claim first, so a concurrent duplicate waits on its row lock and is then skipped. A duplicate counts `iam_org_membership_processed_events_duplicates_total`; the library counts `platform_duplicate_messages_total` itself.
- **`internal/adapter/inbound/consumer/catalog_consumer.go`** — SQS handler for `catalog-orgm-q`, the one queue on Catalog's `iam-catalog-events`: `DepartmentCatalogChanged` clears `om:departments`/`:stale`; `PlanCatalogChanged` (processed_events-deduped) clears `om:plans`/`:stale` and sets `om:plans:gen:{plan}` (`port.PlanGenerationKey`) to the event id, which `AuthZService.getCached` compares against each I-8 entry's `plan_gen` (CACHE-11, LLD rev 2.39). Never writes `tenants.feature_flags` (T-9) — the former `catalog_plans_consumer.go` / `MergeFeatureFlagsForPlan` are deleted. Unknown types go through `dedup.go`'s `ackUnknown`.
- **`internal/adapter/inbound/consumer/membership_event_consumer.go`** — SQS handlers for `tenant-orgm-q`/`billing-orgm-q`. **EVT-14** recency guard (event `time` vs `tenants.last_event_at` under row lock — silently skips stale, still records `processed_events`); **EVT-15** future-time clamp (`event.time > now() + MAX_LIFECYCLE_EVENT_SKEW_SECONDS` → DLQ, not recorded); **EVT-16** tenant-state relay (re-emits `TenantStateChanged` on `iam.membership.events` in the same tx when a consumed event changes `status`/`plan`, sparing Workflow a direct `iam.tenant.events`/`billing.events` subscription); also emits `TenantMembershipsPurged{tenant_id,actor_id}` (renamed from the old `TenantOffboarded`-named relay — that name collided with RP's own terminal event, which Core only consumes) when a consumed event transitions a tenant to `offboarded`, for Delegation/Tender-ACL/Group-Mapping to run their own tenant-scoped cascade-deletes. `TrialReactivated` takes a `port.PlanCatalogReader` dependency to resolve `plan.trial_duration_days` via a pre-tx `CatalogService.PlanByCode` call (mirrors `ProvisioningService.TrialSignup`'s pattern) — fixed from a prior bug where this read a local `plans` table subquery that no longer exists post-ADR-0007.
- **`internal/adapter/outbound/postgres/*_repository.go`** — implements all `core/port` repositories; 7 of the 8 tables carry `record_version` and use `UPDATE ... WHERE id=$1 AND record_version=$2` optimistic locking (409 `optimistic_lock_conflict`, TRG-1 client never sets `record_version`); `processed_events` is the exception. Also: `reconciler_store.go` (`ReconcilerStore`, backs the BYPASSRLS `sysPool`-bound cross-tenant reconciler queries), `gauge_repository.go` (`GaugeRepository` — `CountOwnerlessTenants`/`CountRealmSyncPending`/`CountSeatOverageActive`/`CountPendingInvitationsStale`; `runBusinessExporters` in `exporters.go` takes `*GaugeRepository` directly), and `wrapConnErr` in `db.go` (maps SQLSTATE 08/53/57-except-57014/58 and a closed pool to `domain.ErrDBUnavailable`; a request deadline or `statement_timeout` (57014) or `lock_timeout` (55P03) to 503 `request_timeout`; exhausted deadlock/serialization retries to 409 `conflict`/`concurrent_update`). `db.query` spans come from `gincommon.NewSpanTracer` on `pgcommon.Config.Tracer` for both pools; `PG_STATEMENT_TIMEOUT` is pgcommon's per-transaction `Config.StatementTimeout`, never a DSN option; the system pool's `PoolName` is `system`.
- **`internal/adapter/inbound/sqspipeline/`** — the inbound pipeline every SQS queue runs, outside `cmd/server` so `test/integration` runs it against floci. `NewConsumer` builds the platform-events consumer with this service's defaults (`EnvForQueue`: `SQS_MAX_RECEIVE_COUNT` 4, `SQS_DRAIN_TIMEOUT` 15s, `SQS_HANDLER_TIMEOUT` 20s, `SQS_QUEUE_DEPTH_INTERVAL` 60s; `events.GlueDecodeCodec`; `events.WithDLQForwarding`). `Handler` composes DLQ router → consumer span → `validateConsumed` → `Handle`; `routeRejectsToDLQ` forwards permanent rejects (EVT-15's `ErrPoisonPill`, schema violations) via `DLQPublisher.SendToDLQ`, then acks; a failed send keeps the message on the queue. `RequireDLQ` makes a missing RedrivePolicy fatal at startup.
- **`internal/adapter/outbound/eventbus/glue_codec.go`** — `GlueCodec` (SNS publish side, one per registry): each produced schema's version UUID is resolved **once at startup by definition** (`glue:GetSchemaByDefinition` with the embedded schema in the exact compact form `schema-gov register` uploads — `registeredDefinition`, Python-parity-tested), must be `AVAILABLE`; no refresher, no per-event Glue call; an unregistered definition fails startup. `events.GlueDecodeCodec` — decode-only consumer codec (strips the 18-byte header, no registry), wired on every inbound queue.
- **`internal/adapter/outbound/eventbus/publisher.go`** (enqueue-time `Publisher`) + **`routing_publisher.go`** (`RoutingPublisher`, this service's own local type — not `platform-events` — routes each envelope to one of two pre-built publisher fields via `domain.TopicForEvent(env.Type)`, i.e. event **type**, not `Envelope.Source`; a mixed batch always publishes both lanes and merges their failures into one `*events.BatchError`) + outbox runner; UUID v7 event IDs; `Envelope.Source` is the constant `eventbus.EventSource` (`iam-org-membership`) from both binaries; events with a subject are enqueued with `outbox.EnqueueOrdered` keyed `<tenant_id>/<subject>` under a transaction-scoped advisory lock on that key; `processed_events` composite PK 8-day retention (PE-1 strictly > 7-day SQS lifetime; IDEMP-4 beyond-window duplicates backstopped by EVT-14/PI-10/IDEMP-3). All published events carry `ip_address`/`user_agent` envelope fields (§16 A69); CronJob-originated events use sentinel `ip_address: "system"` / `user_agent: "iam-org-membership/<job-name>-cron"` (`cmd/reconciler/jobs/context.go`).
- **`internal/adapter/outbound/{workflow,realmprovisioner,catalogadmin,groupmappingclient,delegationcheck,tokenservice}/http_client.go`** — six outbound service clients, identical construction pattern (each builds its `http.Client` via **`httpx.NewClient(timeout)`** plus a configurable `*_TIMEOUT_MS` env var). `delegationcheck` (ADR-0008) backs the §8.8.4 dept-scope precision lookup and fails open to tenant-wide scoping; its default timeout is **1000ms** (`DELEGATION_TIMEOUT_MS` — raised from 300ms in Gap-8: the original 300ms caused frequent fallback to tenant-wide impact scoping under load or cold-start). `tokenservice` (AUTH-9/IB-3) backs the service-account-not-grantable check and also fails open. **Note on I-15 callers:** both Delegation Service (`orgmembership/http_client.go`) and Tender ACL Service (`membershipcheck/http_client.go`) call Core's I-15; Delegation was fixed to 1000ms in Gap-8, but Tender ACL still uses the original 300ms default (`MEMBERSHIP_CHECK_TIMEOUT_MS=300`) — the same pre-Gap-8 timeout that caused elevated 503 `core_unavailable` rates for grant calls under load. That fix lives in `iam-tender-acl`, not here. There is no `userprofile/` package — deleted as dead code (LLD §16 OQ-5). **`internal/adapter/outbound/httpx/transport.go`** (`httpx.NewClient`, otelhttp-instrumented `http.Client` factory — `otelhttp.NewTransport` handles W3C `traceparent` injection + client-span emission, and the transport forwards the inbound `x-request-id` via `requestctx.WithRequestID`) **is wired into all six clients** — zero leftover manual `propagateTraceparent`-style helpers.
- **`internal/adapter/outbound/eventbus/schemas/*.json`** — schema-governance workspace, one JSON Schema Draft-07 file per event type, embedded via `//go:embed schemas/*.json` in the `ValidatingCodec`. Derived via `schema-gov extract`; CI `extract --check` for drift. (There is no separate `internal/eventschema/` directory — this is the one workspace.)
- **`api/asyncapi.yaml`** — design-time source of truth for two-topic event contract (`iam.membership.events` + `iam.tenant.events`). `api/openapi.yaml` has been deleted — the REST contract is now `docs/swagger/*` (generated via `make swag`), not hand-authored.
- **`docs/swagger/swagger.yaml`** (generated via `make swag` from handler annotations, not hand-authored) — REST contract for all public/internal/operator routes (P-1..13,24-28,30-31,34; I-1..5,8-11,13-16; O-4,O-7; PUB-1 — 37 total). Retired route IDs (P-14..23,29,32,33; I-6,7,12; O-1,2,3,5,6) are fully unregistered, not 410 Gone, and never reused.
- **`test/postgres/rls_test.go`** — canonical RLS test cases including **Case 5** (critical): no cross-tenant GUC leak across a pooled PgBouncer connection (verifies RLS-6). CI additionally greps for non-`LOCAL` `SET app.tenant_id` as forbidden pattern.
